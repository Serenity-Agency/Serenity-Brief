# Клиентские материалы (/materials/) — SOP

Раздел `brief.serenity.agency/materials/...` — премиальные клиентские one-pager'ы (executive summary, разборы проектов перед встречей). Живёт в том же репозитории и деплое, что и форма приёма брифов, но не пересекается с ней по коду и CSP.

Этот документ — не только техническая инструкция, а порядок действий: кто может публиковать, что проверить перед отправкой клиенту, что делать, если что-то пошло не так.

---

## 1. Роли

- **Аккаунт** — готовит контент, согласовывает с клиентом, что можно показывать, определяет момент отправки ссылки.
- **Технический публикатор** — верстает материал по стандарту, публикует, отвечает за соответствие чек-листу ниже.
- Один человек может совмещать обе роли.

## 2. Важно про доступ: это НЕ приватный хостинг

Страницы **публично доступны любому, у кого есть ссылка**. Логина, пароля или другой проверки личности здесь нет.

`noindex` и `X-Robots-Tag` (в `/materials/*`-блоке `_headers`, генерируется `build-pages.mjs`) — просьба к поисковикам не индексировать, **не защита доступа**.

Единственная фактическая мера — **непредсказуемый URL**: `/materials/<клиент>/<код>/`, например `/materials/acme-corp/x7k2p9/`. Код — случайный, не угадывается перебором. Не публикуйте материал прямо в `/materials/<клиент>/index.html`, всегда с вложенным кодом.

**Что следует из этого:**
- Никаких внутренних номеров сделок, ссылок на amoCRM, внутренней переписки — только то, что можно показать самому клиенту.
- Этот файл, `materials-tools/generate-og.py` и весь остальной репозиторий **вне `materials/`** не деплоятся и не раздаются публично — `build-pages.mjs` копирует в `dist/` только явно перечисленные пути, `materials/` в их числе, всё остальное — нет. Тем не менее: никогда не используйте здесь реальные имена клиентов как примеры, только вымышленные (`acme-corp`) — предосторожность, а не потому что этот файл может утечь.

## 3. Чек-лист перед отправкой клиенту

- [ ] Аккаунт подтвердил: в материале нет ничего, что нельзя показывать клиенту напрямую.
- [ ] Ссылка открыта и проверена на десктопе и телефоне лично.
- [ ] Имя, название компании, цифры в материале — верны и актуальны на момент отправки.
- [ ] Ссылка отправляется напрямую клиенту, не в общий чат/канал.

## 4. Что делать, если...

**Нашли опечатку после отправки клиенту.** Поправить файл в `materials/`, `npm run build:pages`, закоммитить (включая обновлённый `dist/`), запушить в `main` — Cloudflare Pages передеплоит автоматически, ссылка та же.

**Нужно проверить материал до отправки.** Пушьте в отдельную ветку — Cloudflare Pages создаст preview-URL. Смёржите в `main`, когда уверены.

**Нужно закрыть доступ к уже отправленному материалу.** В MVP выборочно нельзя (нет авторизации) — можно только удалить папку клиента из `materials/`.

## 5. Технический раздел

### Структура

```
Serenity-Brief/
├── build-pages.mjs                    — собирает dist/, включая dist/materials/ и CSP-блок для него
├── materials-tools/
│   └── generate-og.py                   — генератор OG-превью, НЕ публикуется (вне materials/)
└── materials/                             — источник, копируется в dist/materials/ целиком
    ├── assets/v1/                            — версионированная дизайн-система
    │   ├── theme.css, app.js, icons.svg
    └── <client-slug>/
        └── <random-code>/
            ├── index.html                          — ссылается на /materials/assets/v1/*
            └── og.jpg
```

`dist/` — коммитится в git (не в `.gitignore`), собирается командой `npm run build:pages` перед каждым коммитом с изменениями в `materials/`.

### CSP-изоляция от формы

`/materials/*`-блок в generated `_headers` (см. `build-pages.mjs`) — отдельная, более мягкая CSP-политика (разрешает Google Fonts), но применяется **только** к путям `/materials/*`. Глобальный `/*`-блок для формы и админки не меняется.

### Правило версионирования assets

`materials/assets/v1/` замораживается, как только на неё ссылается хотя бы один опубликованный клиент. Правки дизайна — только в `materials/assets/v2/`, переключать на неё только новых клиентов.

### Аналитика — пока не подключена

Beacon Cloudflare Web Analytics намеренно не добавлен: рабочего токена на момент публикации LARS House не нашли ни в коде, ни подтверждённым от пользователя. Подключать отдельным шагом после явного подтверждения токена — не восстанавливать плейсхолдер.

## 6. Добавление нового клиента

1. Сгенерировать код: `python3 -c "import secrets,string; a='abcdefghjkmnpqrstuvwxyz23456789'; import random; print(''.join(random.SystemRandom().choice(a) for _ in range(6)))"`
2. Создать `materials/<client-slug>/<код>/`.
3. Скопировать `index.html` предыдущего клиента, заменить контент разделов.
4. Проверить, что `<head>` ссылается на актуальную `/materials/assets/vN/` без изменений.
5. Обновить `canonical`, `og:url`, `og:image`, `twitter:image` на `https://brief.serenity.agency/materials/<client-slug>/<код>/...`.
6. Сгенерировать превью: `python3 materials-tools/generate-og.py --client "Имя клиента" --subtitle "Подзаголовок" --out materials/<client-slug>/<код>/og.jpg`
7. Проверить `<meta name="robots" content="noindex, nofollow">` на месте.
8. Проверить отсутствие внутренних номеров сделок, CRM-ссылок.
9. `npm run build:pages`, локально проверить `dist/materials/<client-slug>/<код>/` (desktop + мобильный, консоль без ошибок), а также что форма и админка не пострадали.
10. Пройти чек-лист перед отправкой (раздел 3).
11. Закоммитить (включая обновлённый `dist/`), запушить в `main` (или сначала в ветку).
12. Записать ссылку во внутренний реестр (вне репозитория).
